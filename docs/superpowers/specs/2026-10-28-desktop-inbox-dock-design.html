底部收件箱面板

在不离开当前任务页面的前提下，随时展开完整收件箱；采用 VS Code 式停靠布局，保留既有完整收件箱路由，两者共享数据但互不抢占导航状态。

状态：待用户确认 范围：Desktop only 方案：经典停靠面板 日期：2026-10-28

一、意图与边界

1

目标

让收件箱成为全局可折叠的常驻工作面板。用户处理任务时无需切走当前主页面，也能查看消息、回复评论和修改任务状态。

2

不替代完整页面

通知点击、搜索、快捷操作和深链仍在主区域打开现有收件箱页面。底部面板不会拦截或改写这些导航。

3

第一版克制

只承载收件箱。容器结构允许未来增加其他标签，但不提前引入聊天、日志、插件系统或通用 Dock API。

二、最终视觉结构

Multica · 当前任务保持不变
收件箱入口隐藏
收件箱8拖动上边缘调整高度⌄
完整任务详情、评论与状态操作
核心行为：展开时主页面缩短，不遮挡内容；收起时只保留底栏。新消息仅更新未读徽标，永不自动展开。

三、已确认的产品决策

主题决定
功能开关设置 → 外观新增独立开关，与“单页签模式”互不依赖。
侧栏入口开关开启时，仅 Desktop 左侧导航隐藏“收件箱”；关闭后恢复。Web 不变。
其他入口通知、链接、搜索和既有快捷操作继续在主区域打开完整收件箱页面。
工作区切换面板不收起，保持高度和开合状态；内容切换为新工作区的收件箱。
启动恢复首次启用默认收起；之后跨重启记住上次开合状态与高度。
消息到达只刷新未读徽标，不自动展开，不抢焦点，不改变主页面。徽标沿用现有侧栏定义，只统计当前工作区的未读收件箱项目。
内容能力与现有收件箱一致：列表、筛选、归档、任务详情、评论与状态修改。

为什么必须抽共享内容层

现有 InboxPage 会同步 URL。直接挂载第二份会让底部选择与主页面路由互相覆盖。拆分后两处共享 TanStack Query 缓存与 mutation，但各自管理当前选中项。

页头处理

主页面保留 PageHeader 和单页签模式 portal；Dock 使用自己的本地标题栏。否则 Dock 的“收件箱”标题会错误地传送到窗口顶栏。

InboxPage
  └─ InboxSurface(controller = routeController, chrome = "page")

InboxDock
  └─ InboxSurface(controller = localController, chrome = "dock")

shared: query cache · mutations · realtime updates · filters

五、Desktop 布局接入

MainCanvas 内停靠

在 MainCanvas 内用纵向可调整布局承载 TabContent 与 InboxDock。这样底部面板与当前圆角画布共用边界，不影响窗口顶栏、侧栏和浮动聊天。

共享侧栏不反向依赖 Desktop

AppSidebar 增加平台传入的 hideInboxNav 属性，默认 false。DesktopShell 从本地偏好读取开关并传入；共享 views 包不导入 Desktop store。

持久化偏好

desktop-prefs-store 增加 enabled、open；升级 store version 并提供默认值。面板高度使用项目现有的 useDefaultLayout 按独立 layout id 持久化。首次启用 open=false，之后原样恢复。选中项、列表滚动和视图状态不跨应用重启持久化。

工作区切换

Dock 外壳不重建；workspace id 变化时切换查询范围并清空旧选中项。面板高度与开合状态保持，避免跨工作区保留无效任务选择。

实现约束：折叠时保留面板内部状态与评论草稿，但必须让隐藏内容不可聚焦、不可读取快捷键，并验证重新展开后虚拟列表和详情滚动尺寸能正确恢复。

六、交互规格

场景行为
底栏点击点击标题或折叠按钮切换开合；标题栏中的筛选、批量操作等控件不触发折叠。
拖拽高度展开后拖动上边缘调整。默认约占画布 38%，最小 260px，最大 70%；窗口变小时自动夹紧。
关闭设置开关立即移除 Dock、恢复侧栏入口；不改变当前主路由，也不清理服务端收件箱状态。
主页面也是收件箱允许上下同时显示。两处数据实时一致，但选择互相独立。
切换工作区保持 Dock 开合与高度，内容切到新工作区并回到列表状态。
新消息更新底栏未读数；不展开、不发出额外产品内动效。
键盘第一版不新增固定快捷键；既有“前往收件箱”仍打开主页面，避免改变用户肌肉记忆。
折叠Dock 内容保持挂载，保留当前选择、滚动位置和现有评论草稿；隐藏内容不可聚焦，也不接收快捷键。
关闭功能卸载 Dock 并丢弃其临时选择与滚动状态；共享 Query 缓存和服务端状态不受影响。评论草稿只遵循现有 IssueDetail 机制，不新增 Dock 专用跨重启持久化。

八、验证与验收

自动化覆盖

  • 偏好 store 的默认值、迁移与持久化。
  • 开关控制 Dock 和侧栏入口。
  • 开合、拖拽、跨工作区保持及选中项重置。
  • 主 Inbox 与 Dock 的选择互不修改对方。
  • 共享 Query 数据与未读徽标同步。
  • 单页签模式开关与 Dock 四种组合。

手工验收

  • 普通页面、设置页、完整收件箱页均可展开。
  • 在 Dock 内回复评论、改状态后主页面立即同步。
  • 折叠/展开不丢正在输入的评论草稿。
  • 缩小窗口时没有遮挡、越界或双滚动条。
  • 浅色/深色主题及 Windows 标题栏覆盖层正常。
  • 关闭开关后现有行为完整恢复。

九、明确不做

  • 不改 Web、Mobile 或服务端 API。
  • 不让 Dock 截获通知、搜索结果或现有收件箱路由。
  • 不在第一版加入聊天、日志、终端或第三方插件标签。
  • 不新增固定快捷键，不更改既有“前往收件箱”行为。
  • 不把 Dock 开合状态同步到服务端或其他设备。
