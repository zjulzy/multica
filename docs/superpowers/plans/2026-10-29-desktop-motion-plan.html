界面动效开关与交互方案

把主题颜色和界面动效分开：用户可独立控制页面动效，同时保留智能体状态提示的清晰表达。

默认关闭Desktop 专属Hub 独立打包前手动验收

开关与范围

在「设置 → 界面」新增“界面动效”开关，设置只保存在本机，与单页签、收件箱 Dock 和智能体 Hub 开关独立。旧设置升级后默认为关闭；切换立即生效。

关闭时去掉下表范围内的装饰性动画，保留加载、进度和焦点等必要反馈。Hub 的运行旋转、排队呼吸和未读涟漪不受此开关控制；系统启用“减少动态效果”时，仍沿用现有无障碍行为。
位置开启时关闭时
页面切换内容轻微淡入与短距离上移；不延迟路由和页面交互。直接显示，不播放装饰性入场。
按钮悬浮轻微提亮，点击有小幅按压反馈。颜色与选中状态仍可辨认，去掉位移和渐变动画。
侧栏导航悬浮、选中状态平滑过渡。状态立即切换；侧栏布局和宽度不受影响。
收件箱 Dock点击按钮展开或收起时平滑变化。点击立即展开或收起。
弹窗与菜单短暂淡入、缩放或轻微位移。弹窗、菜单和提示卡立即出现或关闭。
新消息 / 新任务仅新到达的条目做一次轻微提示。直接显示；虚拟列表滚动和页面首次加载不重复播放。

主题配色作为独立功能，本文不改颜色，也不加入骚粉主题。

手感和安全边界

  • 动效是视觉反馈，不增加网络等待或人为延迟，也不能阻止点击、键盘操作和导航。
  • Dock 手动拖动时直接跟手，绝不套用缓动；中途拖动或反复点击时取消旧动画，最终状态与开关一致。
  • 不改变未读、任务状态、滚动位置、文本输入或窗口布局；不覆盖智能体 Hub 动效。
  • 只影响 Desktop。共享组件若需要增加标记，也不改变 Web / Mobile 原有行为。
  • 弹窗、菜单可能渲染在页面之外，需要确保开关同样对这些浮层生效；不能用一条全局规则关闭所有动画。
  • 遵循系统“减少动态效果”，并保证关闭动效后键盘焦点和关闭弹窗正常工作。

实施步骤

01 · PREFERENCE

设置与兼容

扩展 Desktop 偏好存储、界面开关和现有语言文案；验证旧版迁移、默认关闭、持久化与其他开关互不影响。

02 · MOTION SCOPE

作用域与基础交互

为 Desktop 建立动效状态作用域，处理页面、按钮、侧栏和浮层；确保门户浮层可感知开关，不影响 Hub 和 Web。

03 · DOCK

Dock 展开与拖动

只在按钮触发展开或收起时缓动；拖拽、窗口变化、连续切换和工作区切换均保持正确。

04 · NEW ITEMS

新消息与任务

基于数据更新识别新增条目，只提示一次，避免虚拟列表滚动或重新挂载时重复动画。

05 · VERIFICATION

自动检查与手感验收

覆盖偏好迁移、开关、Portal、Hub 隔离、列表复用和 Dock 连续操作；打开开发窗口让你试用，确认后再打包。

验收重点

  1. 开关默认关闭；打开后页面、按钮、侧栏、Dock、弹窗菜单和新条目都有可感知但克制的反馈。
  2. 开关关闭或系统要求减少动态效果时，装饰性动画停止，功能保持正常。
  3. Hub 状态与它自己的开关独立；运行、排队、未读组合仍按已有规则展示。
  4. Dock 上下拖动依然连续跟手，拖到底仍自动收起；快速反复点击不跳回旧高度。
  5. 切换工作区、长列表滚动、打开多个页面和弹窗时，焦点、滚动位置、状态与原行为一致。
